HelpNest: AI 고객상담 헬프데스크

모든 문의를 티켓으로 모으고, AI가 분류와 답변 초안을 만들어 상담원의 처리 시간을 줄이는 고객센터 시스템입니다. 팀원 세 명이 도메인을 나눠 맡았고, 저는 문의가 티켓이 되어 해결될 때까지 흘러가는 길을 만들었습니다.

기간 2026.09 – 10 역할 티켓 흐름 · 실시간 스택 Spring Boot 4 · Java 21 · Next.js 16 · PostgreSQL 16 · AWS helpnest.kro.kr ↗

맡은 범위 BACKEND + FRONTEND

기능

  • 티켓 CRUD와 상태 전이 규칙, 모든 변경을 이력으로 기록
  • 최소 부하 기반 자동 배정, 팀장의 수동 배정 · 재배정
  • SLA 스케줄러: 첫 응답 기한 80% 경과 · 초과 시 실시간 알림
  • WebSocket(STOMP) 알림과 상담 콘솔의 알림 벨
  • 대기열 기반 1:1 채팅, 상담원이 없으면 문의 티켓으로 전환
  • Next.js 상담 콘솔: 티켓함, 티켓 상세, 채팅, SLA 정책 관리 화면

규칙은 서비스 계층 한 곳에서

  • 허용된 전이와 수행자 권한을 함께 검사하고, 어기면 TICKET_INVALID_TRANSITION
  • 해결 뒤 고객이 다시 답글을 달면 처리 중으로 돌아가는 재문의 처리
  • 배정은 처리 중 건수가 가장 적은 상담원, 같으면 가장 오래 쉰 상담원
  • 상태 · 배정 · 우선순위 변경은 전부 ticket_history에

직접 해결한 문제 CHALLENGES

동시에 들어온 문의가 같은 상담원에게 중복 배정됐다

해결

배정 트랜잭션에서 티켓 행을 SELECT … FOR UPDATE로 잠그고, 최소 부하 → 마지막 배정 시각 → id 순으로 결과를 고정했습니다.

채팅 연결 경합으로 한 고객에게 대기방이 두 개 생겼다

해결

진행 중인 방은 고객당 하나만 있도록 부분 유니크 인덱스로 DB가 강제하게 하고, 방 행을 잠근 뒤 상담원을 연결했습니다.

돌아보며 RETROSPECTIVE

잘된 점

  • 문서와 이벤트 · 인터페이스 계약을 먼저 확정해, 구현 중에 설계를 다시 논의할 일이 거의 없었습니다.
  • 파일마다 주인을 정하고 남의 코드는 Issue로만 요청해, 서로의 코드를 덮어쓰는 충돌이 없었습니다.

다음에 바꿀 점

  • 테스트가 백엔드에 몰려 프론트 화면은 수동 확인에 기댔습니다.
  • CI가 끝나기 전에도 main 머지가 가능했습니다. 브랜치 보호를 더 엄격히 하겠습니다.
